# 存储审计补充：补偿表读取与配方存储重叠

## 结论

**指定 B2.4.1 的 DATA-0、DATA-1 与原厂补偿表读取范围重叠。撤回此前对这两段零区的可复用判断。修复前不建议刷写该版本；不能把此前离线PASS或单机反馈当作排除此问题的依据。**

本次补充完成调用参数、随机跳转表和MA正常处理路径的追踪。硬件辅助函数被替代，因此已确认的是原厂CPU读表和提交缓冲区的数据改变，尚未直接观察相机硬件事务或确定画质后果。

## 1. 两段零区属于仍在读取的表

原厂函数 `0x53632898` 的循环地址为：

```text
address = base + 56 * row + 7 * column + parameter
row = 0..63
column = 0..7
parameter = 0..6
```

七组参数合并覆盖 `64 × 8 × 7 = 3584 = 0xE00` 字节。旧模型按约 `0x1C4 = 452` 字节检查，漏算了外层分块／行循环。

| 原厂表完整范围 `[start,end)` | 被本项目占用的部分 | 读取指令 |
| --- | --- | --- |
| `0x53D39788..0x53D3A588` | DATA-1：`0x53D39C8C..0x53D3A588` | `0x536329A0` |
| `0x53D44EB0..0x53D45CB0` | DATA-0：`0x53D453F8..0x53D45CB0` | `0x53632AE4` |

此前观察到两段“上边界紧贴下一张表”是真实的，但遗漏了从更低基址遍历整表的访问。因此“边界后字节不变”不能支持这两段可用。

### 调用参数与执行反例

对原厂RTOS的直接分支扫描找到6个入口调用位置：

| 调用位置 | 传入入口 `0x53633E6C` 的 r1 |
| --- | ---: |
| `0x5342B384` | 2 |
| `0x534469A8` | 1 |
| `0x53447230` | 4 |
| `0x53633F48` | 0 |
| `0x5365AD60` | 5 |
| `0x5365B0D4`，尾调用 | 4 |

入口把该参数传给各读表函数的r2。已识别参数集合为 `{0,1,2,4,5}`，不是任意负数或超范围输入。参数0通过真实包装入口 `0x53633F38` 执行，其余通过调度入口执行。

| 参数 | 读取占用区次数 | 候选相对原厂改变的读取值 | 改变的32B提交块 |
| --- | ---: | ---: | ---: |
| 0 | 646 | 513 | 19 |
| 1 | 647 | 513 | 19 |
| 2 | 647 | 512 | 19 |
| 4 | 648 | 510 | 19 |
| 5 | 648 | 514 | 19 |

检查方式：

- 使用真实原厂ARM指令，分别装入原厂和指定候选RTOS；两者 `0x53632898..0x53633F54` 指令完全相同。
- 外部硬件／系统辅助函数用替代返回值处理；两个就绪辅助函数返回1，其余返回0。完整入口和返回值登记在 `overlap.json`。
- 记录CPU实际读取的PC、地址、宽度、值；独立按上述公式计算地址集合，五组均完全吻合。
- 在 `0x537375A0` 入口读取r3所指的32B提交缓冲区。调用点为 `0x53632A1C/0x53632B50`。逐项对照原厂与候选，每组均有19块内容不同。
- 辅助函数本身未执行，不把这些缓冲区称为已实测硬件输出；也不从此推断具体RAW/JPEG损坏程度。

## 2. 随机函数的已识别间接入口已解析

`0x536EF3B4` 执行 `LDRLS pc,[pc,r8,LSL #2]`，前置比较将表内索引限制为0..10；表位于 `0x536EF3BC`。

| 索引 | 原厂目标 |
| --- | --- |
| 0 | `0x536EF618`，随机入口 |
| 1..3 | `0x536EF6DC`，固定分支 |
| 4..7 | `0x536EF5C0`，保存组分支 |
| 8 | `0x536EF5E4` |
| 9 | `0x536EF604` |
| 10 | `0x536EF42C` |

只有索引0进入随机入口，而候选将该入口改为跳往固定分支。该跳转表问题已具体解释，不应继续笼统写“没有检查间接入口”。这不等于恢复了原厂随机效果；索引0的行为确实被改变。

## 3. MA零表读取路径

已追踪 `0x536E4470 → 0x536DF484 → 0x536DF55C`：

- 配置记录的 `+0x0C` 引用表指针对象 `0x55019848`；计算函数从对象 `+0x10` 取表指针，保存为临时处理对象的第3项指针。
- 写入函数经该指针读取360个32位值，最后偏移 `0x59C`、宽4B，总范围1440B；再把低10位写进输出参数。
- 在已有tuning仿真环境中，原厂tone 11..22、still/live view两种阶段共24组，各执行原厂与候选一次。正常初始化路径的 `cfg+0x94` 均为0；原厂读取 `0x53DC2BF8..0x53DC3198`，候选读取 `0x53D36400..0x53D369A0`，各360项，所比较的输出一致。

这支持MA正常路径的零表迁移，不消除其他区域的补偿表冲突。单独构造 `cfg+0x94=1` 的诊断输入在输出偏移 `0xA34/0xA35` 有差异；其初始化及真机可达性尚未确认，不能称为相机回归，也不能据此声称全部MA状态等价。

## 处理顺序

1. 将DATA-0/1标为原厂占用区，停止按旧模型分配或宣称安全；当前指定候选不再作为推荐刷写对象。
2. 修正读窗模型与保护清单，加入调用参数、循环公式和执行反例；保护检查应拒绝现有数据布局。此项尚未修改构建器。
3. 将现有配方数据迁出原厂表，优先研究独立追加区；验证加载边界后生成独立候选。
4. 对新布局重新做CPU读窗、完整构建回归及真机验证。不能推荐旧定制版本作为安全替代，因为本次未审计它们。

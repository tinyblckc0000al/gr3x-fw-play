# GR IIIx B2.4.1 存储区域审计

**修复状态（2026-10-17）：** B2.4.2 已将新增数据与辅助代码迁入独立追加区，恢复完整原厂补偿表及此前借用的随机／MA 区域。离线检查通过，用户确认完整加载、开关机、实际 RAW／JPEG 成像正常。见[验证与真机记录](../../../workspace/b2_iiix/VERIFICATION.md)。下文审计对象仍是 B2.4.1，保留原证据与历史结论。

**审计更正：后续追踪已确认 DATA-0、DATA-1 位于原厂补偿表读取范围内。撤回下文初审对其可复用性的判断，修复前不建议刷写指定 B2.4.1。见[补充审计及反例](followup/report.md)。下文保留初审记录，不能作为当前分配依据。**

审计日期：2026-10-17。目标：GR IIIx 官方 1.60 与指定 B2.4.1 BIN。方法：只读静态逆向、引用扫描及二进制对照。本次未进行真机验证。

## 初审结论（已被补充审计更正）

八槽位通过复用原厂区域实现，未新增固件段。当前证据未覆盖全部运行路径。两段数据区紧邻原厂活跃表，应固定现有边界；菜单扩展需先验证独立追加区。

| 已核实的事实 | 对开发的含义 | 不能由此推出 |
| --- | --- | --- |
| 两段数据区末端恰好是原厂活跃表起点；检查的相邻字节未改变 | 冻结现有上边界，先明确保护相邻表 | 零区无人使用；可以继续向后扩 |
| 高斯随机函数的 7 处直接调用均在回收分支；候选改写其入口 | 随机代码属于绕过后回收，有可追溯依据 | 原厂随机效果完整保留；不存在间接入口 |
| MA 表的八个已识别指针全部迁移，目标零表内容相同 | 有明确迁移机制，目标零表须保留 | 原表所有消费者已穷尽 |
| HDF／认证图标被主动替换 | 独立图标存储应优先处理 | 新图标 ID 等于独立像素空间；HDF 已兼容 |

**本轮没有发现所检查边界的越界覆盖。** “没有发现”限于本报告的输入、扫描形态与选定函数；不是刷机安全认证。

开发方向：停止扩大旧区域，先验证追加区的容器、加载与运行时内存边界，再接入菜单、颗粒和画幅。追加文件字节本身不能证明新增内容可被安全加载。

## 存储区域

地址除特别说明外均为 **RTOS 运行时 VA，十六进制**；区间采用 `[start, end)`，不包含 end。不能将 VA 当作 BIN 文件偏移。

| ID | 区间／资源 | 容量 | 原用途 → 当前用途 | 当前判断 |
| --- | --- | ---: | --- | --- |
| DATA-0 | `0x53D453F8..0x53D45CB0` | 2232 B | 原厂零区 → 配方曲线／表／文字等 | 静态证据有限；冻结上边界 |
| DATA-1 | `0x53D39C8C..0x53D3A588` | 2300 B | 原厂零区 → 完整曲线／表等 | 静态证据有限；冻结上边界 |
| CODE-A | `0x536EF61C..0x536EF6DC` | 192 B | Cross 随机分支 → 补丁代码 | 依赖随机入口绕过 |
| CODE-B | `0x536EF6FC..0x536EF998` | 668 B | Cross 随机分支 → 补丁代码 | 同上 |
| CODE-C | `0x536EF088..0x536EF140` | 184 B | 高斯随机辅助函数／常量 → 补丁代码 | 同上；仅穷举了指定形态的直接引用 |
| CODE-D | `0x536EF99C..0x536EF9B8` | 28 B | 随机分支常量／填充 → 回收区 | 同上；邻接活跃代码边界 |
| MA-OLD | `0x53DC2BF8..0x53DC3198` | 1440 B | 原厂零表 → MA 代码／数据 | 依赖八个指针迁移 |
| MA-ZERO | `0x53D36400..0x53D369A0` | 1440 B | 原厂零内容 → 迁移后的零表源 | 必须保留，不能分配写入 |
| ICON | ID `0x05..0x07`、`0x1D` 及新 ID 的像素来源 | 见构建器 | HDF／认证资源 → 预设图标 | 明确替换原厂资源，优先迁出 |

容量不等于本次实际分配量，也不等于剩余空间；MA-ZERO 是保留源，不能加进可分配总量。已有构建账本的 **6236 B / 70 次分配**包含 MA-OLD 内分配，不要再次累加。图标像素与原地修改指令也属于不同统计口径。

### DATA-0 / DATA-1：边界证据

- DATA-0 的上边界 `0x53D45CB0` 是原厂函数 `0x53633C88` 的读表基址，存在 `base + param_3` 读取。
- DATA-1 的上边界 `0x53D3A588` 是 `0x53633B68` 的读表基址，存在 `base + param_3 + 7*i`；循环 i=0..33，跳过两个索引。
- [E3 二进制比较](./comparison.json)确认两段原厂均全零；候选保持 `0x53D45CB0..0x53D45D1C` 的108 B及 `0x53D3A588..0x53D3A678` 的240 B逐字节不变。这是检查范围，不是任意参数下的完整读窗证明。
- [E1 反编译](./ghidra.log)恢复了 `0x53632898/0x53632C2C/0x53633064/0x53633794/0x53633E6C/0x536339E4/0x53633B68/0x53633C88`，确认存在运行时偏移与循环。
- [E4 引用扫描](./data-references.log)对两个占用区未发现可识别引用；**上游 param_3 取值域尚未完整追踪**，不能据此排除从区外基址计算进入的访问。

### CODE-A..D：回收机制

- [E2 ARM census](./arm-census.json)找到高斯函数 `0x536EF088` 的 7 处直接调用：`0x536EF638/0x536EF7A0/0x536EF7E0/0x536EF828/0x536EF870/0x536EF8BC/0x536EF908`，均在 A/B 内。
- 进入四段的已识别直接分支／PC相对读取，来源均在四段内，唯一例外为 `0x536EF618` 读取 `0x536EF9A0`。
- E3确认候选把入口 `0x536EF618` 从字节 `e00bdfed` 改为 `2f0000ea`，即 `B 0x536EF6DC`；它绕过旧随机路径。
- `0x536EF6DC/0x536EF998/0x536EF9B8` 各四字节与原厂相同。这里只抽查入口／边界，不代表整函数不变。
- 仍缺间接跳转表、保存状态与完整随机行为等价性证据。固定子预设的历史仿真结果不能填补这些缺口。

### MA-OLD / MA-ZERO：迁移依赖

E3确认对象 `0x55019848` 的八个指针，由 `0x53DC2BF8` 全部迁到 `0x53D36400`。对象对应 ROM 源地址为 `0x54094D88`，不能把对象运行时地址直接当作文件坐标。

原厂对齐指针统计找到指向 MA-OLD 的八处，恰好对应上述对象。MA-ZERO 的1440 B在原厂／候选中均全零且完全相同。仍缺其他计算地址、指针复制和消费者生命周期的穷尽分析。

### ICON：替换不是空闲

本仓库的构建器与验证策略明确复用 HDF ID `0x05..0x07`、认证 ID `0x1D`；新增 ID 的图像也可切自认证像素区。这是功能取舍，不属于“未使用区域”。本轮未新增 HDF 真机证据。

## 开发约束

1. 先读本页与 manifest，再按证据 ID 找原始文件；不要只引用摘要或搜索命中。
2. 校验输入 SHA256；本报告只绑定指定 IIIx 1.60 / B2.4.1，不授权推广到其他版本或 HDF 运行行为。
3. 使用本仓库的构建器和验证器。原研究工作区另有旧工具副本，不能混用；开始前检查当前提交及工作区状态。
4. 保持“原始观察 → 有限推断 → 未知项 → 开发决策”分层。不要把 `0 references` 改写成 `safe`。
5. 重新分配必须记录完整写区间、对齐、原字节、所有者与依赖；分配不重叠不代表原厂无消费者。
6. 本次只完成静态研究；没有新增相机跟踪、DMA观察或真机回归，也没有验证追加区。不要从报告推断刷机／发布状态。

## 方法限制与易错点

Ghidra 项目以 `-noanalysis` 打开，先读到的六段 XREF 都为0；随后反编译恢复了真实访问。因此这些数据库0值不作为无引用证据。反编译还会提升常量读取位置：`0x536EF9A8` 的实际读取指令在 `0x536EF62C`，应对照E2，而不是仅看伪代码行序。

线性 ARM 扫描可能把数据解码成指令，也未完成 Thumb、全局数据流、间接寻址和硬件消费者分析。报告中的“未发现”均受此限制。文件哈希证明证据身份，不证明结论正确。

以下命令在仓库根目录执行。已验证环境为 Apple Silicon macOS、Python 3.14、Homebrew LLVM，并使用系统字体 `DIN Condensed Bold.ttf`。其他环境未验证。

## 默认固件构建与自测

### 1. 安装依赖

```sh
brew install python@3.14 llvm
"$(brew --prefix python@3.14)/bin/python3.14" -m venv venv
venv/bin/pip install -r requirements.txt
```

### 2. 准备输入

将解压后的官方固件放入以下位置，必须使用指定版本：

| 文件 | 版本 |
|---|---|
| `firmware-inputs/fwdc243b.bin` | [GR IIIx 1.60](https://www.ricoh-imaging.co.jp/english/support/digital/gr3x_s.html) |
| `firmware-inputs/fwdc248b.bin` | [GR IV 1.11](https://www.ricoh-imaging.co.jp/english/support/digital/gr4_s.html)，仅用于提取参数 |

```sh
venv/bin/python scripts/prepare_inputs.py --iiix firmware-inputs/fwdc243b.bin --iv firmware-inputs/fwdc248b.bin
```

输入 SHA256 不匹配时停止；不要替换为其他版本或跳过检查。官方固件不随源码提供。

### 3. 构建默认 B2.4

保持 `presets.json` 和 `fits/` 不变：

```sh
mkdir -p workspace/b2_iiix/out
venv/bin/python workspace/b2_iiix/build_iiix.py --stock iiix --presets workspace/b2_iiix/presets.json workspace/b2_iiix/out/fwdc243b-b24-playback.bin
```

输出为 BIN 及同名 `.report.json`。构建报错后留下的文件不能使用。

### 4. 运行自测

```sh
venv/bin/python workspace/b2_iiix/verify_release.py workspace/b2_iiix/out/fwdc243b-b24-playback.bin
```

#### 测试顺序

1. **先确认对象**：机型、原厂版本和待刷 BIN 必须明确；自己构建时先完成上面的输入检查与构建。修改过配置的版本不属于默认 B2.4，现有冻结版检查器不能直接用于放行。
2. **运行上面的一条自测命令**：脚本依次执行 `selftest → structure → mutations → playback → references → rebuild → regression`。遇到失败会停下，不要单独挑几个通过项作为完整结果。
3. **看最终报告**：打开本次输出目录的 `report.json`，顶层 `status` 应为 `PASS`，七个 `stages` 都应为 `PASS`，命令退出码为 0。某条日志中的 `PASS` 或构建成功不代表整套通过；`hardware: NOT_TESTED` 表示没有替你做真机测试。
4. **有异常先停止**：`FAIL`、`TIMEOUT`、`INCOMPLETE`、`NOT_RUN`、仍为 `RUNNING` 或没有最终报告，都不能据此刷机。查看第一个未通过阶段对应的 `.log`；修正原因后重跑完整流程。超时可调整时限，不要删除检查、修改预期指纹或关闭断言。
5. **最后核对实际写卡文件**：默认 B2.4 全部通过后，将 BIN 按首页说明放到卡内，并核对卡内文件的 SHA256。检查后又改了配置或重新生成文件，就必须重新核验。

> 直接使用发布成品的用户无需搭建开发环境重跑仿真，但仍需确认兼容范围及卡内 BIN 指纹与发布值一致。核对下载完整性不代表对相机安全作保证。

检查及其目的如下；这些检查针对默认 B2.4，不等于对任意修改版的安全保证。

| 检查 | 主要避免的问题 | 对应实现 |
|---|---|---|
| 输入指纹、修改前指令字节 | 用错固件版本，补丁写错地址 | `prepare_inputs.py`、补丁写入前的预期值检查 |
| 分配边界、重叠、写入范围及保护区 | 覆盖原厂代码或 ISP 数据，引发死机、RAW 损坏或画面异常 | `verify_release.py` 的 `structure`、`rebuild` |
| 原厂地址引用扫描 | 把仍被原厂引用的数据区误当作空闲区 | `references`；线性扫描不能证明不存在间接引用 |
| 容器校验和、分区布局 | 打包损坏或布局变化导致无法加载 | `structure` |
| 菜单计数、回放映射和 ARM 仿真 | 预设缺项、图标空白、错误分支或破坏原厂模式（含 Cross Process） | `playback`、`regression` |
| 故障注入、检查工具自测 | 检查器漏报，出现假通过 | `selftest`、`mutations`；仅覆盖已设置的错误案例 |
| 确定性重建 | 相同配置生成不同结果，发布文件与验证对象不一致 | `rebuild`，与冻结的 B2.4 指纹比较 |

所有阶段 `PASS`、退出码为 0 才算完成；失败、超时、跳过或中断均不算通过。分配记录来自构建器，仿真也只覆盖设定路径，无法完整模拟传感器、存储卡和实时任务；RAW/DNG 是否正常仍需真机拍摄及读片确认。

下载或复制到卡后，可按首页的文件校验方法核对 BIN，避免刷入错文件或不完整的副本；这一步不属于固件功能测试。
独立关机图片包另核对脚本生成图片与目标图是否一致、格式尺寸及备份和重复执行保护；安装后的读回图片与实际显示仍须单独确认。

- 报告：`workspace/b2_iiix/logs/qualification-*`。
- 默认每阶段超时 1800 秒，可用 `--timeout` 调整。
- 不使用 `python -O` 或 `PYTHONOPTIMIZE`，避免禁用断言检查。
- [文件指纹见首页](../../README.md#文件校验)，不要修改预期值来绕过检查。

默认 B2.4 通过后，将输出文件复制并命名为 `fwdc243b.bin`，按[首页安装说明](../../README.md#固件直接安装步骤)操作。电脑端检查不能代替相机自测。

#### 测试说明

以下路径以仓库根目录为起点。“可单独运行”不等于一个文件拷走就能用：除检查工具自测外，多数还依赖仓库模块、Python 依赖、指定固件或配方。

| 文件 | 用来查什么 | 能否单独使用及限制 |
|---|---|---|
| `scripts/prepare_inputs.py` | 输入是否为指定的 IIIx / IV 原厂固件，并准备构建输入 | **可单独运行**；只验证输入，不测试生成的固件 |
| `workspace/b2_iiix/verify_release.py` | 默认 B2.4 的完整电脑端流程与汇总报告 | 首选入口；依赖指定原厂固件、仓库脚本和默认配方，只接受冻结的 B2.4 |
| `workspace/b2_iiix/verification.py` | 地址引用、映射、保护区、分配与写入范围的检查规则 | 库文件，没有独立命令入口；供检查器和单元测试调用 |
| `workspace/b2_iiix/test_verification.py` | 检查器是否能识别构造的越界、重叠和引用等错误 | **可独立运行**，不需要真机或固件文件；通过只说明这些检查规则的测试通过 |
| `workspace/b2_iiix/test_playback.py` | 最终 BIN 中的回放解析链，含原厂、新增及边界输入 | **可直接运行**，但读取代码中的默认 B2.4 路径；指定其他路径用下方分阶段入口，不把 BIN 当作 unittest 参数 |
| `tools/gr3-film-mods/verify_slots16.py` | 菜单、图标、色彩参数、模式切换及 RAW 显影等仿真回归 | **可直接运行**，但须传入原厂 BIN、候选 BIN 和按槽位顺序排列的配方；推荐由完整入口自动组装参数。直接运行不能只看退出码，要检查 `FAIL` 和最终 `ALL OK` |
| `workspace/b2_iiix/verify_offline.py` | 补充观察容器往返、修改分布、部分原厂模式及 Cross Process 的渲染差异 | 旧的诊断工具，不是完整放行检查。只抽验部分模式；`FAILED` 不一定产生非零退出码，且部分校验先修复校验和再计算，不能证明输入原有校验和正确 |

只想定位某一阶段时，可从仓库根目录运行：

```sh
# 测试检查器自身，第二条只执行回放仿真
venv/bin/python -m unittest discover -s workspace/b2_iiix -p 'test_verification.py'
# `--stage` 是排查入口，不生成完整汇总报告，也不执行其他阶段；局部通过不能代替第 4 节的完整命令
venv/bin/python workspace/b2_iiix/verify_release.py workspace/b2_iiix/out/fwdc243b-b24-playback.bin --stage playback
```

#### 自己扩展改动任意代码，组织测试时请至少覆盖以下方面

- **文件与写入**：输入身份、修改前字节、容器与布局、全部修改范围、分配边界与对齐、保护区及原厂引用。
- **功能与边界**：全部新增槽位和原厂模式；快捷菜单、MENU、拍摄、回放、机内 RAW 显影的编号与计数；合法边界、越界输入，以及胶片切回原厂模式的状态恢复。
- **检查器与可复现性**：故意破坏数据确认能报错；相同输入重建一致；记录配置、依赖、BIN 指纹和完整日志。
- **实机与文件读取**：按下一节顺序检查，逐套拍 RAW+JPEG，实际解码 RAW，确认回放、原厂模式及开关机表现。电脑测试不能替代这一项。

增加槽位、改变空间布局或移植版本时，还需重新审查地址、容量和检查期望值。没有对应检查的项目应记为“未覆盖”，不能通过修改 SHA 或沿用旧报告补成通过。

### 5. 相机自测参考

按下面顺序逐步检查；前一步异常就停止后面的项目步骤。
准备已备份的备用卡和充满电的电池，先记录已有设置；更新期间不要断电或拔卡。

| 顺序 | 操作 | 观察结果 |
|---|---|---|
| 1 | 更新完成后正常开机，先进入快捷菜单和 MENU → 影像控制 | 菜单能进入、退出，原厂与新增预设可选，无卡死或异常重启 |
| 2 | 用一套原厂预设拍一组 RAW+JPEG，回放后拷到电脑 | 两个文件都能完整打开；RAW 要实际解码，不只看内嵌缩略图 |
| 3 | 每套新增预设各拍一组 RAW+JPEG，记录文件名与所选预设 | 回放名称、图标和可见参数与选择相符；电脑读片无解码错误、明显坏块或条带 |
| 4 | 新增预设 → Cross Process → Standard 来回切换并拍摄；检查机内 RAW 显影 | 切回原厂后无明显残留异常，显影可完成；单看缩略图或能保存文件不够 |
| 5 | 正常关机再开机，重复进入菜单与拍摄 | 设置保存符合预期，无日期反复重置、卡异常或新增死机 |

保留配置、报告、操作顺序和异常原片。出现异常停止继续拍摄测试，参考首页的恢复说明；刷机过程中不要因为等待时间长而贸然断电。上述观察只能发现部分问题，无法证明 RAW/DNG 完全干净或长期稳定。

这些是个人项目的自测参考，不代表全部已覆盖。当前仅有单台普通 IIIx 的反馈，留存样片覆盖七套新增预设；其他机型和长期稳定性未验证。

真机问题再附操作顺序、文件名与原始 RAW/JPEG；分享前检查日志中的个人路径及照片元数据。不必先上传完整固件，也不要只截一行 `PASS`。

## 自定义预设

### 配置文件与可修改内容

`presets.json` 只定义 tone 编号与 `fits/` 文件的对应关系；配方文件保存曲线和色彩参数，其 `preset` 块定义 `name`、`icon_label`、`icon_rgb`、`full_curve`。图标 ID 由构建代码分配。

- 保留键 `25–32` 和八个槽位；当前配置加载器固定要求此范围。
- 图标标签为 1–4 个可打印 ASCII 字符，颜色为三个 0–255 整数。模板形状需修改源码。
- 名称、颜色和曲线等改动都会改变文件指纹。现有 `verify_release.py` 只接受默认 B2.4，不能作为自定义固件的通用校验入口，也不要改掉预期指纹来绕过检查。

### 图标与配置编辑

图标 ID 是代码中的查找编号，图标外观是根据配方生成的像素，两者分开处理。拍摄屏与回放使用同一组 `ICON_IDS`；想改名称、标签或颜色时，**不要改 ID**。

例如，在某个 `fits/*.json` 中修改现有 `preset` 块里的这些字段，其他字段保持原值：

```json
{
  "name": "Classic Neg",
  "icon_label": "NC",
  "icon_rgb": [60, 90, 140]
}
```

`icon_rgb` 控制**标签文字颜色**，不是底色。40×40 胶片轮廓以原厂 Positive Film 图标为模板，由 `make_icons.py::render` 绘制；修改底色、轮廓或尺寸属于源码改动。`full_curve` 决定曲线存储方式，影响空间占用，不要作为外观设置随意切换。

编辑前备份配方，保留数据结构、数组维度和必需字段；配置加载器检查 JSON、数值及部分容量限制，但不证明色彩正确或真机行为正常。源码 ZIP 可用于构建，不能当固件直接刷入；需配齐构建指南中的输入和依赖。

### 调整默认预设顺序

`presets.json` 指定八个槽位对应的 `fits/` 文件。复制配置后交换文件名即可调整顺序，保持键 `25–32` 和八套预设不变。例如交换前两套：

```json
{
  "25": "ektar100.json",
  "26": "portra400.json",
  "27": "gold200.json",
  "28": "pro400h.json",
  "29": "vision3-250d.json",
  "30": "classic-negative.json",
  "31": "vision3-500t.json",
  "32": "velvia50.json"
}
```

保存为 `workspace/b2_iiix/presets-example.json`：

```sh
venv/bin/python workspace/b2_iiix/presets_config.py workspace/b2_iiix/presets-example.json
venv/bin/python workspace/b2_iiix/build_iiix.py --stock iiix --presets workspace/b2_iiix/presets-example.json workspace/b2_iiix/out/fwdc243b-example.bin
```

这只生成候选文件。默认自测入口固定检查 B2.4，会拒绝修改后的产物；自定义完整检查流程尚未补齐，不应将构建成功视为可以刷入。新配方制作和内部参数编辑不在本说明范围内。

## 实现原理与扩展约束

### 实现原理

实现上复用原厂影像控制框架：将选定的旧记录槽位改造成新增预设记录，写入各自的色彩参数，并补充名称、图标和相关映射。菜单修复补上 `GetMaxCount` 的数量限制；回放修复扩展“EXIF → 播放枚举 → 显示 tone → 图标”三层映射，保留原厂条目。新增代码和数据放在指定空间内，最后重新打包固件并更新校验值，而不是直接向 BIN 末尾追加内容。

### 扩展槽位数量（进阶）

以下用于修改扩槽实现或移植固件；默认八套构建无需调整。地址是当前补丁的定位参考，不是通用文件偏移，移植时需重新确认指令和引用。

#### 1. 记录槽位与配置入口

`make_slots15.py` 使用以下旧记录槽位，为新增配方复制共享的 Standard 记录，并写入各自的色彩矩阵：

```python
LEGACY_SLOTS = (1, 2, 3, 4, 5, 7, 9, 8, 6)
assert 1 <= n <= len(LEGACY_SLOTS)
```

这只是底层列出的九个候选位置。当前 `presets_config.py` 固定接收八套、键为 `25–32`；第九套还要检查字符串、图标、曲线空间及所有映射，不能由此认定“还可以直接加一套”。超过九套则需重新设计记录存储。

#### 2. 图标资源与兼容性

```python
ICON_IDS = (0x05, 0x06, 0x07, 0x1D, 0x2D, 0x2E, 0x2A0, 0x2A1, 0x2A2)
NEW_ICON0, ICON_BOUND = 0x2A0, 0x29E
```

按现有源码的资源识别，前六个 ID 复用 HDF 开关状态、IIIx 认证标志及 TELE/71mm 裁切图标；后三个使用新增描述符。默认八套使用前八个 ID。

新 ID 通过补丁接入图标宽度、高度和绘制三个已知消费点。扩展时需检查其他直接索引图标表或判断上界的代码。HDF 等机型可能实际使用这些被复用的图标，不能直接套用；影响不限于新增预设自己的显示。

#### 3. 编号、计数与回放链路

Custom 1/2 使用显示 tone 23/24，新增胶片从 25 开始；默认八套的照片 ImageTone 编码为 `0x10C–0x113`（268–275）。显示 tone、照片编码和图标 ID 不是同一个编号。

| 补丁位置 | 用途 |
|---|---|
| `0x532C2ACC` | `GetCount` 内的数量指令，供拍摄列表使用；不是函数入口 |
| `0x532C2B7C` | `GetMaxCount`，供 MENU 列表使用 |
| `0x53283C08` | RAW 显影列表计数 |

修改数量时还需同步 index↔tone 表、EXIF 写入/解析和回放的“EXIF → 播放枚举 → 显示 tone → 图标”三层映射。只改计数可能让列表出现选项，却无法正确选择或回放。菜单计数中 `12 + m` 不含两套 Custom，相关列表总数为 `12 + m + 2`；不要把这些期望值混用。

#### 4. 空间预算与打包

B2.4 的 `PRESERVE_SPANS` 为两段半开区间：

| 区间 | 总容量 |
|---|---|
| `0x53D453F8–0x53D45CB0` | 2232 字节 |
| `0x53D39C8C–0x53D3A588` | 2300 字节 |

这些是区域总容量，**不是当前剩余空间**。普通三通道 knot 曲线占 198 字节，`full_curve` 三通道完整曲线占 1536 字节，此外还有表、对齐及其他分配开销。钩子代码和图标像素也有各自的借用区域，不能把所有容量相加当成任意可用空间。应以构建报告和分配器实际结果为准。

原厂可能读取看似空白的区域，不能未经引用和读取范围审计就扩大空间。构建保持 section 布局，经解码、修改、重新打包和校验；文件长度相同不等于内容有效。

#### 5. 原厂模式回归与验证

新增配方会使用曲线表指针。preserve 路径恢复共享指针，并保留 tone 21（Cross Process）的原厂分支，防止上一套胶片状态影响后续原厂模式。
改动后应检查“胶片 → Cross Process → 其他原厂模式”的切换，不只是单独渲染一张照片。

扩展还需补齐配置对应的映射、边界、原厂模式与仿真测试。现有 `verify_release.py` 通过固定 SHA256 验证默认 B2.4，会拒绝新的构建；修改计数期望或替换指纹都不能代替完整的自定义验证。
